# Modal에서 학습

`modaltest.py`는 데이터 준비를 CPU에서 실행한 뒤 RTX PRO 6000 Blackwell 96GB 한 장으로
사전학습 → 대화 학습 → 모델 저장 → 평가를 실행합니다.
Python 3.11과 `requirements-native-600m.txt`의 패키지는 원격 이미지에 설치합니다.
Blackwell 호환성을 위해 PyTorch 2.8.0의 CUDA 12.8 빌드를 먼저 설치합니다.
로컬 PC에는 Modal SDK와 저장소만 필요합니다.

VRAM은 이전 A100-80GB의 80GB에서 96GB로 20% 증가합니다.
`gpu="RTX-PRO-6000"`으로 한 장만 요청하며 컨테이너도 최대 1개입니다.
CPU 24코어와 시스템 RAM 64GiB는 유지합니다. 시스템 RAM과 GPU VRAM은 별도 자원입니다.
GPU 종류별 시간당 요금은 다르므로 [현재 요금](https://modal.com/pricing)을 확인하십시오.

`rtx-pro-6000` 프로필은 사전학습 배치 8 × 누적 8,
대화 학습 배치 8 × 누적 4를 사용합니다. 기존과 동일한 유효 배치 64·32를 유지하며,
실제 처리 속도와 VRAM 사용량은 실행 환경에서 확인해야 합니다.
전체 메모리가 80GiB 이상인 RTX PRO 6000에서는 중간 활성값을 VRAM에 보관하고,
메모리 절약을 위한 활성값 재계산을 끕니다. 체크포인트 파일 저장·재개는 유지합니다.
시작 로그에 GPU 이름, 전체 VRAM, 정밀도, 배치·누적 횟수와 재계산 여부를 표시합니다.
기존 배치 1 × 누적 64로 학습한 체크포인트도 배치 8 × 누적 8로 재개합니다.
유효 배치, 데이터·토크나이저 해시, 정밀도, 학습 예산과 다른 학습 옵션이 같아야 합니다.
가중치·옵티마이저·난수 상태·다음 샘플 위치를 복원하며 `[resume] batch_size=1 -> 8`로 알립니다.
원래 실행 식별자는 보존하고 실제 배치는 `execution_options`에 기록합니다.
검증에 쓰는 창의 수는 원래 실행과 같게 유지합니다. 배치 묶음이 달라지므로 부동소수점
계산 결과의 비트 단위 일치는 보장하지 않습니다.
GPU 변경으로 가중치를 초기화하거나 데이터·토크나이저·토큰을 다시 만들지 않습니다.

## 실행

저장소 루트에서 Modal SDK를 설치하고 계정을 연결한 뒤 실행합니다.

```bash
python -m pip install -r requirements-modal.txt
modal setup
modal run modaltest.py
```

명령이 실행되는 동안 터미널을 유지하십시오. 데이터 준비가 완료된 뒤 GPU 작업을
요청하므로 다운로드와 토크나이저 학습 중에는 GPU를 할당하지 않습니다.
CPU 24코어를 요청하며 문서 정규화·필터링은 24개 CPU 프로세스에서 수행합니다. 중복 제거·분할·저장은 입력
순서대로 처리하여 결과를 재현하며, 대기 작업 수를 제한하여 메모리 사용량을 억제합니다.
다운로드나 저장 속도가 병목이면 CPU 사용률이 낮을 수 있습니다.
데이터 준비만 먼저 수행할 수도 있습니다.

```bash
modal run modaltest.py --prepare-only
```

데이터 준비 후 2 step의 GPU 실행을 확인하려면 다음 명령을 사용합니다.
`--smoke`도 준비된 전체 데이터를 사용하며, 데이터가 없으면 먼저 준비합니다.
시험 실행의 체크포인트는 본학습과 다른 디렉터리에 저장합니다.

```bash
modal run modaltest.py --smoke
```

## 저장 위치와 실행 제한

`native-korean-600m` Volume을 `/training`에 연결합니다.

| 항목 | 컨테이너 내부 경로 |
|---|---|
| Hugging Face 데이터 캐시 | `/training/huggingface` |
| 준비된 데이터·토크나이저·토큰 | `/training/artifacts_native_600m/{data,tokenizer,tokens}` |
| 사전학습·대화 학습 체크포인트 | `/training/artifacts_native_600m/{pretrain,sft}` |
| 최종 모델 | `/training/artifacts_native_600m/model` |
| 평가 보고서 | `/training/artifacts_native_600m/evaluation.json` |
| 2 step 시험 실행 | `/training/artifacts_native_600m_smoke/pretrain` |

완료된 전처리 단계는 해시와 설정을 검사한 뒤 재사용합니다.
재사용 검증과 토큰 변환 전의 데이터 검증에도 24개 CPU 프로세스를 사용합니다.
파일별 해시는 최대 4개 스레드에서 동시에 확인하고, JSON 해석·정규화·분할 검사는
프로세스로 분산합니다. 중복 검사는 분할 전체를 대상으로 유지하며 대기 작업 수를
제한합니다. `[verify:...]` 로그에 해시 검사 바이트 수와 검증 기록 수를 표시합니다.
한 파일의 SHA-256 계산이나 저장소 읽기가 병목인 구간은 모든 코어를 사용하지 않을 수 있습니다.

실제 문서·대화 토큰 변환도 24개 프로세스에서 배치 단위로 수행합니다.
각 작업자는 JSON 해석, 토큰화, 도우미 마스크 생성, uint16 변환까지 처리하며,
주 프로세스는 원래 순서대로 결과를 저장합니다. 저장하면서 해시를 계산하므로
생성 직후 토큰 파일 전체를 다시 읽을 필요가 없습니다. 토큰 파일 재사용 검사도
분할별 프로세스로 분산하며, 분할 수가 4개이므로 이 구간은 최대 4개 작업자가 실행됩니다.

토크나이저 어휘 학습은 Rust 내부의 24개 스레드를 사용합니다.
토큰 변환 작업자는 각각 Rust 스레드를 1개로 제한하여 24×24개의 스레드가 생성되는
것을 방지합니다. `[tokenizer:...]`, `[hash:...]`, `[tokenize:...]` 로그에서 단계와
진행 상황을 확인할 수 있습니다. 하나의 어휘를 만드는 BPE 병합, 파일별 SHA-256 체인,
결과의 순차 저장은 모든 구간을 24개 프로세스로 나눌 수 있는 작업이 아닙니다.

같은 Volume과 설정으로 다시 실행하면 완료된 데이터·토크나이저·토큰 파일은 검증 후
재사용합니다. 진행 중 중단한 토큰 변환은 완료 명세가 없으므로 해당 변환 단계부터
처음부터 다시 수행합니다.
데이터 준비가 완료된 후 네이티브 라이브러리의 종료 충돌로 `SIGABRT`가 발생하면,
완료 명세가 있는 경우에 한해 별도 프로세스로 전체 데이터의 해시·기록 수·분할·출처를
검증합니다. 검증을 통과해야 다음 단계로 진행하며, 미완성 자료나 다른 단계의 오류는
그대로 실패 처리합니다. 검증 프로세스는 데이터를 다시 다운로드하지 않습니다.
같은 설정으로 다시 실행하면 학습기가 저장된 `last.pt`에서 재개합니다.
새 실행과 재개 모두 첫 번째 학습 step이 끝나면 저장하며, 이후에는 약 5분마다
완료된 step에서 `last.pt`를 원자적으로 교체합니다. 기존 step·검증·완료 시점 저장도 유지합니다.
학습기의 `--checkpoint-seconds`로 시간 간격을 바꿀 수 있으며, 전처리 설정이나 실행 식별자에는
영향을 주지 않습니다. 처음 검증 손실을 계산해 `best.pt`도 조기에 생성합니다.
체크포인트 파일은 Volume의 백그라운드 커밋으로 지속 반영되고 명령 종료 시 명시적으로 커밋합니다.
코드 변경은 이미 실행 중인 컨테이너에 반영되지 않습니다. 저장하지 않은 진행 상황은
재시작 시 복원할 수 없으며, `last.pt`가 없으면 step 0부터 시작한다는 로그를 표시합니다.
기존 `checkpoints_600m_ko/`는 업로드하거나 불러오지 않습니다.
동일한 Volume의 결과 디렉터리에 여러 학습을 동시에 실행하지 마십시오.

각 CPU/GPU 함수의 실행 제한은 1시간이며 자동 재시도는 설정하지 않습니다.
오류가 발생하면 해당 실행을 중단하고, 이미 저장한 결과는 Volume에 보존합니다.
기본 사전학습 예산은 여전히 120억 토큰이며 30분 또는 1시간 안에 완료된다는
의미는 아닙니다. 실행 시간에 맞게 학습량을 변경하려면
`configs/native_600m.json`의 `pretrain.target_tokens`와 `sft.epochs`를 조정하십시오.
기존 결과가 있는 상태에서 설정을 변경하면 재개 검증이 실패하므로 새 Volume 또는
새 결과 경로를 사용하십시오.

평가 기준을 통과하지 못하면 모델과 평가 보고서를 보존하고 종료 코드 1을 반환합니다.
이는 GPU 학습 실행 오류와 구분하여 보고서를 확인해야 합니다.
